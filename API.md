# API Documentation

> India Airfare Price Observatory — REST API reference (APIX-2.0/2.2)

All endpoints are served under `/api/v1` (a handful of legacy viewer endpoints ship unprefixed for the lightweight static UI at `/ui`). Interactive, always-current documentation is auto-generated by FastAPI and available at:

- **Swagger UI:** `http://localhost:8000/docs`
- **ReDoc:** `http://localhost:8000/redoc`
- **Raw OpenAPI schema:** `http://localhost:8000/openapi.json`

This document is a curated map of that schema, grouped the same way the interactive docs group them, with the intent behind each group explained. Treat `/docs` as the source of truth for exact request/response schemas; treat this file as the "why does this endpoint exist" guide.

---

## Conventions

- **Read-only by design.** Every `GET` endpoint below is safe to call without authentication (PRD §55: public statistical endpoints are read-only). The handful of `POST` endpoints trigger real collection/computation work and are intended for operators, not public consumers.
- **Methodology transparency.** Index-producing endpoints (`/index`, `/index/timeseries`, `/index/monthly`, `/index/dual-series`) include `methodology_version`, `weight_version`, `coverage_rate`, and `is_low_coverage` in their response — never a bare number with no provenance (PRD §41, §78).
- **JSON everywhere** except the `/export/*.csv` endpoints, which return `text/csv` for spreadsheet/researcher consumption.
- **Errors** use standard HTTP status codes with a structured `detail` body; a source or computation being unavailable returns a real error rather than a fabricated `200` with placeholder data (PRD §54, "Do not silently retry forever" / "must never silently produce apparently valid data").

## Public National Indices

The headline product surface — what PRD §42 calls out explicitly.

| Method | Path | Purpose |
|---|---|---|
| GET | `/index` | Current headline index value, daily/weekly/monthly change, coverage rate, methodology version (PRD §42 `GET /api/v1/index`) |
| GET | `/index/daily` | Daily airfare price index time-series (APIX-2.0) |
| GET | `/index/timeseries` | Daily index series over an arbitrary date range |
| GET | `/index/dual-series` | HEADLINE (raw Laspeyres) vs CORE (festival/peak-exclusion-guarded) series side by side |
| GET | `/index/monthly` | Monthly-aggregated index, for direct comparison against MoSPI's monthly CPI cadence |
| GET | `/weights` | Current and historical DGCA-derived route weights, versioned (`weight_version`) |
| GET | `/data-quality` | Valid/rejected/missing/duplicate/low-coverage counts and coverage-over-time |
| GET | `/methodology` | Full methodology spec: base period, price estimator, missing-data method, outlier method, formula, weight version — answers "how did you calculate this number?" without reading source code (PRD §51) |

## Corridor Intelligence

Route-level drill-down and the T+45→T+1 lead-time curve (PRD's "Lead-Time Elasticity" signature feature, §76).

| Method | Path | Purpose |
|---|---|---|
| GET | `/corridors` | List the monitored domestic route basket |
| GET | `/corridors/{pair}` | Fare breakdown and intelligence for one corridor |
| GET | `/lead-time` | T+45/T+30/T+15/T+7/T+1 representative fares for a route, with the T+1/T+45 ratio dynamically computed from actual observations (never hard-coded, per PRD §76) |
| GET | `/validation` | Prototype-vs-benchmark scorecard: correlation, MAE, RMSE, directional accuracy (PRD §33) |
| GET | `/validation/dgca` | Cross-check against the DGCA fare benchmark specifically |

## Multi-OTA & Carrier Pricing

Cross-feed governance — comparing what each of the six OTAs quotes against the carrier-direct reference price, the basis for markup/discrepancy auditing.

| Method | Path | Purpose |
|---|---|---|
| GET | `/validation/cross-feed` | Carrier-direct vs OTA price reconciliation for a corridor |
| GET | `/validation/source-pair` | Pairwise markup/discrepancy between two named sources |
| POST | `/ota/source-pair-audit` | Trigger a fresh source-pair audit run |
| GET | `/validation/source-correlation` | Rolling correlation between a source and the carrier-direct reference |
| POST | `/validation/compute-source-correlation` | Recompute source correlation |
| GET | `/ota/common-flights` | Flights quoted identically across multiple OTAs (matching basis for markup comparison) |
| GET | `/ota/dispersion-ranking` | Which OTAs run consistently high/low vs the reference |
| GET | `/ota/sources-status` | Per-OTA health/enablement snapshot |

## Live Scraper Pipeline

Operational endpoints for the collection engine itself (source health, manual triggers). These are the ones an operator or the scheduled Task Scheduler / GitHub Actions job calls, not a public dashboard consumer.

| Method | Path | Purpose |
|---|---|---|
| GET | `/quotes/live` | Most recently ingested real quotes (raw ingestion feed) |
| POST | `/collection/run` | Trigger a real-world scraper ingestion cycle |
| POST | `/live/collect` | Trigger a targeted live collection |
| POST | `/collection/trigger-cycle` | Trigger the full 10-route × 5-horizon collection cycle (same entry point `CollectionScheduler.trigger_collection_cycle` uses) |
| GET | `/source-health` | Per-source status: HEALTHY / WARNING / DEGRADED / DOWN / DISABLED, success rate, latency, last successful run (PRD §49, §52) |

## Relationship to the PRD's minimum API spec

PRD §42 lists 12 required endpoints (`/index`, `/index/daily`, `/index/monthly`, `/routes`, `/routes/{route_id}`, `/routes/{route_id}/index`, `/routes/{route_id}/lead-time`, `/weights`, `/validation`, `/data-quality`, `/source-health`, `/methodology`). All 12 are implemented — `/routes` is served as `/corridors` and `/corridors/{pair}` (the project's route-basket naming convention throughout), and route-scoped lead-time is served as `/lead-time` with a route parameter rather than nested under `/routes/{id}/lead-time`. Every other endpoint in this document is additive: OTA governance, forecasting, policy intelligence, and researcher exports are all beyond the PRD's P0/P1 scope.
